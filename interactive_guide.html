Week 1–2 · Lab 1 The Messages Lab

The single most important structure in the course: a list of {role, content} dicts. Models are stateless — "memory" is just resending the whole list every call. Build one yourself:

// the smallest possible conversation
messages = [{"role": "user", "content": "Hello, GPT!"}]
response = openai.chat.completions.create(model="gpt-4.1-mini", messages=messages)
reply = response.choices[0].message.content   // always this exact chain!

Week 1–2 · Lab 2 The Streaming Lab

With stream=True the reply arrives as many small chunks — each carrying a fragment in .delta.content. The Python trick: a generator that yields the partial text, pauses, and resumes on the next chunk.

def stream_reply(messages):
    stream = openai.chat.completions.create(model=MODEL, messages=messages, stream=True)
    result = ""
    for chunk in stream:
        result += chunk.choices[0].delta.content or ""   // .delta, not .message!
        yield result          // ← pause, hand partial text to the UI, resume later

Week 2 · Lab 3 The Tool-Calling Round Trip

The model cannot run code. It can only write a "work order" in JSON — your Python executes it. Step through the exact 4-step round trip that powers every AI agent:

tools = [{"type": "function", "function": {"name": "get_ticket_price", "description": "Get the price of a return ticket…",
   "parameters": {…}}}]
response = openai.chat.completions.create(model=MODEL, messages=messages, tools=tools)
while response.choices[0].finish_reason == "tool_calls":   // ← THE AGENT LOOP
    message = response.choices[0].message
    messages.append(message)                       // append the REQUEST (required!)
    args = json.loads(message.tool_calls[0].function.arguments)  // a JSON STRING, not a dict
    result = get_ticket_price(args["destination_city"])          // YOUR function, YOUR machine
    messages.append({"role": "tool", "content": result, "tool_call_id": message.tool_calls[0].id})
    response = openai.chat.completions.create(model=MODEL, messages=messages, tools=tools)

Week 3 · Lab 6 Tokens & Quantization

Models read tokens — ~4-character chunks mapped to numbers — and store their billions of learned numbers ("weights") as 16-bit floats. Quantization shrinks each to fewer bits: smaller, faster, slightly blurrier.

✂️ Fake tokenizer

Real tokenizers are model-specific vocabulary lookups (try tokenizer.apply_chat_template()) — but the idea is the same: text becomes numbers, cost & length are counted in tokens.

Week 6–7 · Lab 8 The Training Heartbeat

Every neural network that has ever been trained runs this 5-step drumbeat, millions of times. Watch the loss fall — then flip the overfitting switch and watch validation loss betray you:

for epoch in range(EPOCHS):
    for X_batch, y_batch in loader:
        optimizer.zero_grad()          // 1 erase last round's notes
        outputs = model(X_batch)        // 2 FORWARD: guess
        loss = loss_fn(outputs, y)      // 3 SCORE: how wrong?
        loss.backward()                 // 4 BACKWARD: blame every weight
        optimizer.step()                // 5 NUDGE every weight downhill
